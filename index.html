02

Problem

Traffy Fondue is a LINE account where Bangkok residents report broken roads, flooding, dark streets and more. They send a photo, the location and a short message, and the report goes to the office in charge.

Over one million complaints later [1], two things make the data hard to use. People pick the problem category themselves, so many reports land in the wrong category, and from November 2025 the category is empty for every complaint. Fixing speed is also very uneven: one complaint in our sample was fixed in under a day, another took 269 days. The city has no simple view of which problems and which areas are slow.

Research question

Can we label Traffy Fondue complaints by problem type from their text, including text translated from other languages, and use those labels to show how fast each type of problem is fixed in each Bangkok district?

Text labelling

Which model best predicts the problem type from the text, and which complaints were likely filed in the wrong category?

Translation

After machine translation between Thai and English, does the model still label complaints correctly?

Speed and areas

Which problem types and districts are fixed fast or slow, and which districts group together?

What changed after Milestone 1. Ajarn found the data interesting but noted our team cannot read the Thai text. He suggested an app to monitor problems and fixing speed by area and type, and labelling problem types from text because user-chosen categories can be wrong.

Text labelling is now our main task. Translation helps us read and test the text, and the results feed an interactive monitoring app.

Related work

  • Machine learning already sorts public complaints in other countries [2].
  • On Traffy Fondue, a 2024 study built a multi-label text model for complaints filed under "Others" [3], and a Thai language model fine-tuned on Traffy text is public on Hugging Face [4]. Our text model must match or beat them.
  • A student project, Sed-Young-Wa, predicted fixing time with one regression model, with an average error of about 20 [5].
  • The full review, with 10 or more recent papers, comes by Milestone 4.

Cleaning plan

  • Remove duplicate tickets and early test records from 2021.
  • Split rows with several categories into multi-label targets.
  • Clean the Thai text (links, emojis, extra spaces) and cut it into words with a Thai tokenizer.
  • Fixing time is last update minus report time, finished cases only, with extreme values checked.

04

Method

We follow CRISP-DM. Every model is compared on the same split: train on 2022 to 2024, test on 2025.

  1. Understand and prepare the data

    Explore categories, districts and time patterns, then clean the text and labels.

  2. Label problem types from text

    Baseline: TF-IDF with Logistic Regression. Compared: Linear SVM, Random Forest and a fine-tuned Thai language model (WangchanBERTa), checked against the published Traffy model [4]. Measured by: micro and macro F1 and Hamming loss.

  3. Test translation

    Translate a sample from Thai to English with an open translation model and compare labelling accuracy on both. In the app demo, complaints in other languages are translated to Thai before labelling.

  4. Measure speed and group districts

    Classify fast or slow with Logistic Regression (baseline), Random Forest and XGBoost, measured by F1 and ROC-AUC. Group the 50 districts with k-means and hierarchical clustering, measured by silhouette score.

  5. Explain and build the monitoring app

    Use SHAP to show what makes a complaint slow, then build an interactive app: filter by district and problem type, see fixing speed, and read complaints in English.
